Systems Guide

What journals actually do

BSJ is no longer just “record skills, read them later.” The current build layers in reward types, claim rules, restoration states, batching, and server-specific progression safety.

Recording Claiming Restored vs persistent Claim limits Forget slots Batching

Recording progress

  • Personal journals can record skills, traits, recipes, and stats if those tabs are enabled.
  • Baseline restriction prevents starting profession bonuses from being stored as if they were earned later.
  • Some compatibility toggles exist to exclude progress sources that servers may not want journals to replay.

Claiming and learning

  • Most rewards are learned through timed actions instead of instant buttons.
  • Reading speed can be influenced by the Reading skill if that option is enabled.
  • Skill book multipliers can optionally affect loot-journal XP while leaving personal journals on their own recovery model.

Persistent vs restored journals

Persistent journals

These behave like reusable personal journals and do not auto-dissolve just because their contents were claimed once.

Restored journals

These preserve their loot-origin state and can either persist or dissolve based on server settings.

Limited-claim loot journals

Servers can force worn, bloody, and cursed reward journals to dissolve after a set number of successful claims.

  • This is a loot-journal rule, not the default model for normal persistent personal journals.
  • Already-known or blocked claims are handled differently from successful claims.

Forget slots

Forget slots are special journal rewards that let a player remove a negative trait rather than gain a normal upgrade.

  • Worn, bloody, cursed, and Yuletide journals can all be configured to roll them.
  • They give loot journals value even when their raw stats are not a direct upgrade for the current character.

Batch actions

  • Batch size controls how many entries “Record All” or “Absorb All” processes in one action.
  • Batch time multiplier controls how long grouped actions take.
  • Servers can keep the classic one-at-a-time feel or move toward faster large-journal handling.
