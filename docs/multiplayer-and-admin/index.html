Server Play

Multiplayer and admin-facing rules

BSJ's multiplayer surface is mostly about trust, progression safety, and recovery. Permissions, baseline restriction, and snapshot tools matter much more here than they do in casual solo play.

Sharing personal journals

  • Servers can allow other players to open personal journals.
  • Servers can separately allow or deny claiming from someone else's personal journal.
  • These permissions mostly matter for player-authored journals, not standard loot journals.

Baseline handling

  • Baseline restriction prevents profession starts from becoming farmable journal loops.
  • This matters most on servers where death and reroll behavior would otherwise let players abuse starting bonuses.
  • The current UI also exposes baseline-clearing and cache-clearing controls for repairing mismatched character state.

Baseline snapshots

  • The dev build introduces SteamID-anchored baseline snapshots for safer admin recovery and rollback.
  • Servers can enable snapshot storage, cap how many are retained, and decide when they auto-capture.

Admin and debug-adjacent behavior

These are not normal player-facing systems. The current build includes debug and recovery controls intended for moderation, testing, or repair.
  • Baseline reset tools can repair broken journal-state assumptions.
  • Debug commands can be explicitly enabled for testing.
  • Snapshot tooling exists to make progression recovery safer than ad-hoc fixes.
